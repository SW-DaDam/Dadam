## 1. 개요 (Overview)

### 1.1 배경 및 필요성

- 통계청에 따르면 대한민국은 2025년 **초고령사회**(65세 이상 20% 이상)에 진입했으며, **1인 고령가구**가 빠르게 증가 중
- 고령층의 **사회적 고립·고독사·인지 저하** 문제는 사회적 이슈로 부상했으며, 가족과의 단절이 핵심 원인
- 기존 시니어 케어 서비스는 **감시·모니터링** 중심이라 어르신의 심리적 저항이 크고, 어르신을 "보호 대상"으로만 다룸
- 전화·문자는 빈도가 낮고 기록으로 남지 않으며, 어르신이 먼저 말을 꺼내기 어려움
- 대화형 AI 기술의 발전으로 **매일의 말동무**가 가능해졌고, LLM 기반 서사 생성으로 **개인의 일상을 책으로 엮는 경험**이 가능
- 기존 "시니어 케어 앱"은 포화 상태이지만, **어르신을 저자로 세우는 출판 플랫폼**은 블루오션

### 1.2 프로젝트 비전

> AI와의 일상 대화가 어르신의 책이 되고, 그 책을 가족이 읽고 댓글로 이어가는
> **"한 집안의 출판 플랫폼"** 개발

어르신은 **저자(Author)**, 가족은 **독자(Reader)**, AI는 **고스트라이터(Ghostwriter)**.
매일의 대화가 쌓여 한 달의 책이 되고, 1년 뒤 가족 모두가 함께 쓴 자서전이 완성된다.

## 2. 목표 (Goals)

### 2.1 최종 목표

AI 말동무와의 일상 대화를 어르신의 **월간 책**으로 자동 생성하고, 가족이 그 책을 읽고 댓글로 참여하는 **가족 출판 플랫폼 웹 서비스** 개발

### 2.2 세부 목표

| 구분 | 범위 | 내용 |
|------|------|------|
| 세부 목표 1 | **MVP** | Web Speech API 기반 실시간 AI 말동무 음성 대화 시스템 구축 |
| 세부 목표 2 | **MVP** | 관심사 메모리 누적 및 AI의 기억 기반 선제 대화 기능 구현 |
| 세부 목표 3 | **MVP** | 월말 AI 자동 책 초안 생성 + 어르신 간단 편집 + 표지 이미지 생성 |
| 세부 목표 4 | **MVP** | 가족 1:N 초대 및 책장 UI + 챕터 단위 댓글 커뮤니티 |
| 세부 목표 5 | 향후 고도화 | 합본(6개월/1년) 자동 생성, 인쇄 제본 연동, 댓글 → 책 반영 순환 고도화 |

### 2.3 성공 지표 (KPI)

- Web Speech API 기반 음성 대화 정상 동작률 90% 이상 (Chrome/Edge 기준)
- 관심사 메모리 기반 AI 선제 대화 정확도 80% 이상 (사용자 평가)
- 월간 책 초안 자동 생성 요청 대비 정상 응답률 95% 이상
- 어르신 승인 후 가족 책장 출간까지 End-to-End 플로우 안정 동작
- Vercel + Supabase 배포 및 서비스 가용성 확인
- 데모용 시연: 실제 "한 권의 책" 산출물 생성 가능

## 3. 사용자 (Users & Personas)

### 3.1 타깃 사용자

#### 주 타깃
- **어르신(저자)**: 65세 이상, 가족과 떨어져 사는 시니어
  - 디지털 숙련도 낮음
  - 타이핑 어렵고 **음성 입력 선호**
  - 손주·자식 이야기를 가장 좋아함
  - 하루의 대부분을 혼자 보냄

#### 부 타깃
- **가족(독자)**: 30~60대 자녀·손주
  - 평일 바쁨, 주말에만 시간 여유
  - 부모·조부모에게 자주 연락 못 해 **죄책감**이 있음
  - 스마트폰 / 태블릿 / 데스크톱 다양한 기기 사용

### 3.2 사용자 구조

- **어르신 1명 : 가족 N명** (1:N 연결)
- 가족끼리는 서로의 댓글·하이라이트 공유됨 (모든 가족 공개)

### 3.3 사용자 시나리오

#### 시나리오 1: 어르신의 하루
> 김순자 어르신(72)은 아침 9시에 거실 태블릿을 켜고 "말동무 시작"을 누른다.
> AI가 "어르신, 지난주에 토마토 수확했다고 하셨죠? 어떠셨어요?"라고 먼저 말을 건넨다.
> 30분 동안 대화를 나누고, AI가 "오늘도 좋은 이야기 들려주셔서 감사해요"라고 마무리한다.

#### 시나리오 2: 월말 책 출간
> 4월 말, AI가 "어르신, 이번 달 책을 이렇게 써봤어요"라며 초안을 보여준다.
> 어르신은 "이 챕터는 빼줘", "제목은 '토마토가 익던 4월'이 좋겠어"라고 음성으로 편집한다.
> AI가 제안한 3개의 표지 이미지 중 하나를 고르면, 가족 책장에 책이 출간되고 가족들에게 알림이 간다.

#### 시나리오 3: 가족의 독서와 댓글
> 아들(45)은 퇴근 후 어머니의 새 책을 펼친다.
> "그때 저도 기억나요. 중학교 때 엄마가 토마토 따주신 날…"이라고 챕터에 댓글을 단다.
> 다음 날 AI는 어르신에게 "아드님이 그때 기억난다고 댓글 남겼네요"라고 전하고,
> 어르신의 답변은 다음 달 책의 새 재료가 된다.

## 4. 기능 요구사항 (Functional Requirements)

### 4.1 1단계: 기반 시스템 구축

#### FR-1.1 인증 및 사용자 관리
- 어르신 계정 + 가족 계정 분리
- 가족 초대 링크/코드 방식 (1:N)
- Supabase Auth 기반 (이메일/소셜)
- 어르신은 가족이 대신 계정을 생성·설정해주는 것을 가정

#### FR-1.2 데이터 모델 및 DB 설계
- 어르신 프로필, 관심사 메모리, 대화 기록, 책, 챕터, 댓글, 가족 관계 데이터 모델 및 ERD 설계
- 개인정보보호법 준수: 최소 수집 원칙, 데이터 보유 기간 명시
- 어르신의 대화 원문은 **어르신 본인만 접근 가능**, 책은 가족 공개

#### FR-1.3 시니어 친화 UI 기본 구현
- **아날로그 책장 메타포** — 책꽂이·책 넘김 애니메이션
- 큰 글씨, 높은 대비, 단순한 화면 구조
- **음성 주력 + 텍스트 + 큰 버튼** 3중 입력 지원
- 한 화면에 한 가지 행동만 유도 (Progressive Disclosure)

> **[설계결정 Q4]** "감시 앱"이 아닌 "책장"으로 심리적 프레임 차별화 — §11.2-1 "저자로서의 어르신" 정체성과 직결.
> **[설계결정 Q5]** 3중 입력(음성·텍스트·버튼)을 모두 제공 — 어르신마다 숙련도·선호가 달라 하나만으로는 접근성 한계. 음성은 실패 시 텍스트/버튼으로 fallback.

### 4.2 2단계: AI 말동무 (Layer 1)

#### FR-2.1 실시간 음성 대화
- **Web Speech API** 기반 STT/TTS (Chrome/Edge)
- `lang='ko-KR'`, TTS `rate=0.9` (시니어 친화)
- 음성 실패 시 텍스트 입력 대체 제공
- 대화 중 끊김·오인식 자동 복구 흐름

#### FR-2.2 관심사 메모리 시스템
- 각 대화 세션 종료 시 LLM이 대화에서 다음을 추출
  - 취미/관심사, 작물/반려동물, 이웃/지역 소식, 추억/옛이야기, 관계 언급, 철학·가치관
- 누적 프로파일 형태로 DB 저장 및 갱신
- 어르신 전용 "내 이야기 메모" 화면에서 확인 가능

#### FR-2.3 AI 기억 기반 선제 대화
- 대화 시작 시 관심사 메모리에서 **화제 후보** 자동 선별
- "지난주 토마토 익으셨다고 했는데 맛있게 드셨어요?" 같은 연결형 발화
- 예정 이벤트(병원, 가족 방문 등) 자동 리마인드

#### FR-2.4 발화 태그 분류
- 각 발화에 자동 태그 부여
  - `daily_mundane` (제외 후보)
  - `memory_recall` (추억)
  - `emotional_peak` (감정)
  - `philosophy` (가치관)
  - `relationship_event` (관계 사건)
- 월말 책 재료 선별의 기초 데이터로 활용

### 4.3 3단계: 월간 책 시스템 (Layer 2, 핵심)

#### FR-3.1 월말 책 초안 자동 생성
- 매월 말 지난 한 달 대화의 **10~20%만** 엑기스로 선별
- 반복 빈도·감정 강도·서사성 가중치 적용
- **주제 기반 챕터 구성** (가족/추억/일상/가치관 등) + 챕터 내 시간 흐름 자연 서술
- 챕터당 최대 4쪽, 총 3~5개 챕터
- 초안은 **LLM 기반 서사 생성**으로 문장화

> **[설계결정 Q3]** 시간순 나열 대신 주제 기반 챕터 채택 — 일기가 아닌 "책다움"과 서사성을 확보하기 위한 구조적 선택.

#### FR-3.2 어르신 편집 기능 (최소 권한)
- 음성/버튼으로 다음 편집 가능
  - 챕터·문장 **빼기**
  - 챕터 **제목 바꾸기**
- "한 번에 하나" 원칙 UI (시니어 친화)
- Error Recovery > Prevention: 모든 편집은 되돌리기 가능

> **[설계결정 Q1]** 편집 범위를 "빼기 + 제목 바꾸기"로 의도적으로 좁게 제한 — 시니어 UX의 "한 번에 하나" 원칙 및 편집 부담 최소화.

#### FR-3.3 책 표지 및 제목 생성
- AI가 표지 이미지 **3~5개 후보** 생성 (DALL-E 3 등)
- 어르신이 그중 하나 선택
- 책 제목은 AI 제안 + 어르신 최종 선택
- 헌사·에필로그 녹음은 선택 기능으로 제공

#### FR-3.4 조기 출간 (주제 분량 기준)
- 기본: **월간 고정**
- 예외: 특정 주제의 분량이 모바일 기준 **5~7페이지**에 도달하면 그 주제 단편으로 조기 출간
- 예: "손주 민준이 방문" 이야기가 풍부해지면 월간 책과 별개로 단편 출간

> **[설계결정 Q6]** 월간 리듬으로 "기다림"을 만들되, 풍성한 주제는 단편 즉시 출간해 "신선함"도 확보 — 두 가치의 균형.

#### FR-3.5 출간 및 가족 알림
- 어르신 승인 시 책장에 꽂히고 모든 가족에게 알림 발송
- 가족 책장 UI에 신간 표시

### 4.4 4단계: 가족 커뮤니티 (Layer 2 확장)

#### FR-4.1 가족 책장 UI
- **아날로그 책꽂이 메타포**로 월간 책 시각화
- 책별 조회수·댓글 수 표시
- 집필 중인 책은 "(집필 중)" 표시

#### FR-4.2 챕터 단위 댓글
- 챕터 또는 문장 단위로 댓글 작성
- **모든 가족 공개** — 형제·가족 간 댓글 공유
- 댓글은 다음 달 AI 대화 재료로 활용 (순환 구조)

> **[설계결정 Q2]** 댓글을 어르신·형제·세대 모두에게 공개 — 1:1 비공개가 아니라 "공동 독서"가 되어야 가족 단절 해소라는 핵심 가치에 부합.

#### FR-4.3 어르신 답장 기능
- 가족 댓글에 **음성으로 답장** 가능
- AI가 음성을 텍스트로 변환해 답글로 저장
- 어르신 답장 내용은 다음 달 책의 챕터 재료가 됨

#### FR-4.4 하이라이트 _(Phase 2 후보)_
- 가족이 책 문장에 밑줄·하이라이트
- 가족별 하이라이트는 공유 아카이브에 축적

### 4.5 5단계: 합본 및 인쇄 _(향후 고도화)_

#### FR-5.1 합본 자동 생성 _(향후 고도화)_
- 6개월·1년 단위 월간 책 자동 재편성
- 주제 식별, 서사 흐름 재구성, 중복 제거
- "어머니의 2026년 봄·여름" 같은 타이틀로 합본 생성

#### FR-5.2 인쇄 제본 연동 _(향후 고도화)_
- 월간 책 / 합본 인쇄 주문
- 하드커버 양장본, 디자인 커스텀 등 프리미엄 옵션
- 배송 관리

#### FR-5.3 가족 사진 첨부 _(향후 고도화)_
- 가족이 어르신의 책 챕터에 사진을 기증하는 기능
- 어르신 기억 + 가족 사진 결합 아카이브

### 4.6 6단계: 통합 테스트 및 배포

#### FR-6.1 통합 테스트
- 어르신-가족 End-to-End 시나리오 테스트
- 음성 인식 성공률 시니어 대상 실사용 테스트
- 월간 책 초안 품질 평가

#### FR-6.2 성능 최적화

## 5. 비기능 요구사항 (Non-Functional Requirements)

### 5.1 보안 및 프라이버시
- Supabase Auth + RLS(Row Level Security) 기반 접근 제어
- **어르신 대화 원문**은 어르신 본인만 접근 (가족 접근 불가)
- 책(출간본)만 가족에게 공개
- Supabase 기본 저장 암호화(at-rest) + HTTPS 전 구간 통신
- LLM API 키는 Supabase Edge Functions 내부에서만 사용, 클라이언트 노출 금지
- 회원 탈퇴 시 개인정보 및 대화 데이터 즉시 삭제
- **감시·모니터링 기능 일체 없음** — 서비스 정체성 유지의 핵심

### 5.2 성능
- 음성 대화 응답 지연 최소화 (스트리밍 활용)
- Web Speech API 브라우저 호환성 fallback 전략
- 월말 책 생성 배치 작업은 백그라운드 처리

### 5.3 접근성 (시니어 친화)
- **한 손 한 손가락으로 조작 가능**
- 최소 글자 크기 준수, 고대비 색상
- 음성 중심 UX, 타이핑 선택 사항
- 모든 행동은 되돌리기 가능 (Error Recovery > Prevention)
- 사용 통제권을 어르신에게 부여 (Locus of Control)

### 5.4 확장성
- 누적 관심사 메모리로 AI 대화 품질 지속 향상
- 월간 책 데이터를 학습·통계용 별도 테이블에 저장
- Vercel AI SDK 기반 모델 추상화로 Gemini·GPT·Claude 등 엔진 유연 교체

## 11. 차별화 포인트

### 11.1 기존 서비스 vs 본 프로젝트 비교

| 구분 | 기존 시니어 케어 앱 | 본 프로젝트 (가족 출판 플랫폼) |
|------|-------------------|-------------------------------|
| 어르신 위상 | 관찰·보호 대상 | **저자(Author)** |
| 가족 위상 | 모니터링하는 사람 | **독자(Reader)** |
| 핵심 행위 | 건강·일상 리포트 확인 | **책 집필·출간·독서·댓글** |
| 프라이버시 | 여러 안전장치 필요 | 자연스럽게 해소 (어르신이 편집권자) |
| 심리적 프레임 | 감시 | 창작 |
| 공유 자산 | 일회성 리포트 | 세대를 넘는 **유산(Legacy)** |
| 어르신 유인 | 없음 (가족이 요구) | 매달 책 출간에 대한 **기대·설렘** |
| 가족 참여 동기 | 의무감 | **자연스러운 독서·댓글** |
| 비즈니스 모델 | 구독·광고 | **인쇄 제본** (자연 도출) |
| 데모 임팩트 | 대시보드 | **실물 한 권의 책** |

### 11.2 3대 핵심 차별화

1. **"저자로서의 어르신"**: 감시가 아닌 창작 프레임 — 심리적 저항 ZERO
2. **AI 기억 기반 선제 대화**: 관심사 메모리 누적으로 "진짜 말동무"가 됨
3. **순환 구조**: 댓글 → 어르신 답변 → 다음 달 책 재료 → 댓글 — 대화가 끊기지 않는 가족 출판 플랫폼

## 14. 활용 방안 및 기대 효과

### 14.1 활용 방안

- **어르신 개인**: 매일의 말동무 + 매달 자신의 책이라는 **창작 루틴** 획득
- **가족 전체**: 어머니·아버지의 일상을 **책이라는 형태로** 공유받고 댓글로 대화 재개
- **세대 유산**: 1년·수년에 걸쳐 축적된 합본은 돌아가신 후에도 남는 **디지털 자서전**
- **커뮤니티 확장**: 장기적으로 어르신 간 익명 이야기 공유 가능성

### 14.2 기대 효과

#### 기술적 측면
- Vercel AI SDK 기반 **LLM 추상화 + 프롬프트 엔지니어링** 역량 확보
- 관심사 메모리 누적 기반 **장기 컨텍스트 설계** 경험
- Web Speech API 기반 **시니어 친화 음성 UX** 구현 노하우
- 대화 → 서사 자동 생성이라는 **LLM 기반 서사 파이프라인** 설계 경험

#### 사회경제적 측면
- 고령층 고독·고립 문제의 **심리적 저항 없는** 해결책 제시
- 가족 관계 회복의 새로운 모델 제시 (감시 → 공동 창작)
- 시니어 디지털 소외 문제의 **음성 중심** 접근으로 해소
- 인쇄 제본 시장과의 자연스러운 결합으로 **신규 비즈니스 모델** 검증

#### 산업적 측면
- "시니어 케어 앱" 포화 시장에서 **출판 플랫폼**이라는 블루오션 제시
- AI 기반 **개인 서사 생성** 기술의 상용 사례
- 가족 중심 **디지털 유산 아카이브**라는 새로운 카테고리 개척
